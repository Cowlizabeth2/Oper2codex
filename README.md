# Оперативный центр

Автономное настольное приложение для Windows 10/11: независимые карточки происшествий, визуальный конструктор, произвольные текстовые шаблоны, контакты Excel, рабочие документы и справочные файлы. Python 3.12 / PySide6 6.8 / QML / SQLite. Интерфейс на русском языке.

[Исходное техническое задание](docs/TECHNICAL_SPEC.md) · [Актуальный редизайн 0.2 и изображения](docs/REDESIGN.md) · [История проверок версии 0.1](docs/VALIDATION.md).

[Скачать Windows-сборку 0.2](https://github.com/Cowlizabeth2/Oper2codex/actions/runs/40097314789): откройте **Artifacts → OperationalCenter-Windows**. 54 теста Windows, 36 визуальных снимков и проверка запуска собранного EXE пройдены. Распакуйте вложенный ZIP целиком и запустите `ЗАПУСТИТЬ.bat`. Word/Excel, вставка в рабочие мессенджеры и целевой Windows 10/11 требуют ручной приёмки.

## Запуск из исходников

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux: source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python main.py
```

Точка входа только `main.py`. Данные по умолчанию находятся в `%LOCALAPPDATA%\OperationalCenter` (Linux: `~/.local/share/OperationalCenter`). Для изолированной проверки: `python main.py --data-dir /путь/к/тестовой/папке`. Не используйте рабочие документы для тестов.

```sh
python -m pytest -q
python main.py --smoke-test --smoke-report artifacts/source-smoke.json
```

На Linux без дисплея задайте `QT_QPA_PLATFORM=offscreen`, `QT_QUICK_BACKEND=software`, при необходимости `XDG_CACHE_HOME=/tmp/oper-cache`. Smoke-test всегда создаёт собственную временную БД; открывает рабочую карточку, четыре редактора блоков, историю, настройки, журнал и главную. QML warnings/errors делают проверку неуспешной. Он не открывает исходные документы внешними приложениями.

## Обновление и сборка Windows

Первичная установка: загрузите в GitHub весь проект вместе с `.github/workflows/build-windows.yml` и `source_bundle.zip`. Workflow запускается после push в `main` или вручную через Actions → Build Windows → Run workflow. После этого для обновления с телефона достаточно заменить **один `source_bundle.zip` в корне**. ZIP содержит файлы проекта непосредственно в корне, а не дополнительную папку.

После правки исходников создавайте актуальный ZIP:

```sh
python tools/make_bundle.py
```

Входом сборки всегда является ZIP с проверяемым SHA-256-манифестом. Исходники вне ZIP не подмешиваются. Не загружайте сторонние непроверенные ZIP: сборка исполняет код приложения. Проверка архива защищает пути и целостность, но не подтверждает доверие к автору.

Windows runner устанавливает зависимости, запускает тесты, нативную проверку CF_HDROP, загружает QML, собирает PyInstaller-пакет и запускает **собранный EXE** с таймаутом. Артефакт `OperationalCenter-Windows` появляется только после успешной проверки. Распакуйте вложенный ZIP целиком и запускайте `ЗАПУСТИТЬ.bat`. На целевом ПК не нужен Python или интернет. Неподписанный EXE может потребовать разрешения ИТ-службы.

## Архитектура

- `domain.py`: UUID, конфигурация, сегменты шаблона, валидация.
- `storage.py`: транзакции, миграции, снимки событий, предпочтения, журнал, backup API SQLite.
- `files.py`: копии без перезаписи, манифест до копирования, независимые комплекты событий, защищённый просмотр.
- `contacts.py`: создание XLSX, точные теги, несколько действий, кэш с явным предупреждением об устаревании.
- `controller.py`: Qt-мост без SQL в QML.
- `theme.py`, `qml/Theme.qml`: единые токены оформления.
- `qml/`: рабочее место, холст и стрелки, панели свойств.
- `tools/`: безопасное извлечение ZIP, воспроизводимый source bundle, сборка Windows.
