# Редизайн 0.2 — результаты и проверка

Обновление существующего `Cowlizabeth2/Oper2codex` по [заданию](REDESIGN_REQUEST.md). [Карта компонентов](COMPONENT_MAP.md) объясняет устройство и совместимость данных.

## Что изменилось

- Боковое меню сворачивается до иконок; вкладки и действия занимают компактную верхнюю область.
- Главная показывает компактные мастер-кнопки и последние события. История — таблица с поиском и фильтрами статуса.
- Сообщение состоит из постоянного текста и встроенных однострочных/многострочных полей. Отдельного нижнего предпросмотра нет. У каждого поля собственное раскрывающееся меню фраз, UUID и режим замены/добавления. Одна кнопка копирует точный исходный порядок, пробелы и переводы строк.
- Конструктор разделён на палитру, холст и инспектор. Поддержаны Ctrl-выделение и рамка, групповое перемещение, Ctrl+C/V/D, восемь зон изменения размера, сетка, направляющие по краям и центрам, средняя кнопка / пробел для перемещения холста, Ctrl+колесо для масштаба и вписывание.
- Связи имеют отдельный режим со стрелками и портами. Щелчок по линии удаляет связь после подтверждения. Порты позволяют подключать отдельные экземпляры; все связанные блоки активируются вместе.
- Свойства разделены на сворачиваемые секции. Для текста есть расширенный редактор и читаемые обозначения полей. Сохранение оформления не теряет несохранённый шаблон.
- Контакты и файлы представлены компактными строками с действиями справа. Рабочие копии документов, Excel-теги, файловый буфер и защита исходников сохраняют прежнюю логику.
- У карточки есть собственная история действий. Масштаб UI сохраняется отдельно от масштаба холста.

## Данные и обновление

Сделайте резервную копию базы через настройки и отдельно сохраните документы. Замените папку программы; `%LOCALAPPDATA%\OperationalCenter` сохраняется. Для SQL-схемы миграция не потребовалась. Автотест проверяет побайтовую сохранность сериализованных старых снимков/значений при чтении новым интерфейсом, стабильные UUID и восстановление из резервной копии.

Существующие размеры блоков не уменьшаются автоматически. В рабочей карточке используется обычный масштаб с прокруткой; кнопка «Вписать» меняет представление. В конструкторе пользователь сам может уменьшить старые блоки. Новые экземпляры получают компактный исходный размер 400×280.

## Локальные проверки 24 октября 2026

Локально: **53 passed, 1 skipped**, код завершения 0, Python 3.12.14 / PySide6 6.8.3. Пропущен только нативный Windows CF_HDROP. Итоги находятся в `artifacts/tests.xml`, `source-smoke.json`, `visual/report.json`, `visual-125/report.json`. Запуск QML и визуальная матрица — без предупреждений. Windows-прогон новой версии должен подтвердить нативные проверки и EXE; сборка 0.1 не считается проверкой редизайна 0.2.

Проверка QML проходит по всем страницам и редакторам, создаёт событие, импортирует Excel, копирует документ и возвращает реальный код завершения. GUI-тесты выделяют текст мышью, создают поле, вводят значения, раскрывают меню фраз и выбирают пункт, копируют сообщение, переключают независимые события, перемещают/растягивают блоки и удаляют связь щелчком по стрелке.

Визуальная матрица: обе темы × шесть страниц × окна 1920×1080 и 1366×768, плюс обе темы × шесть страниц при `QT_SCALE_FACTOR=1.25`. Это 36 реальных снимков, с проверкой размеров окна, размера изображения, DPR и отсутствия предупреждений QML. Эффективное масштабирование Qt моделирует 125%; системную настройку DPI конкретного рабочего ПК нужно проверить отдельно.

## Что требует проверки на рабочем ПК

Открытие в установленном Word/Excel/PDF, вставка в конкретные мессенджеры и Проводник, корпоративные ограничения неподписанного EXE, реальные мониторы/DPI Windows 10/11 и привычная оператору компоновка. Проверки GitHub Actions выполняются на Windows Server runner и не заменяют приёмку на целевом ПК. Работа с большими файлами/Excel по-прежнему синхронная; при создании большого комплекта возможно ожидание интерфейса. Undo/redo конструктора хранится в памяти текущего запуска, сам черновик — в SQLite.


На Windows runner оконный менеджер ограничил клиентскую область примерно до 1028×749. GUI-тесты используют нативную платформу Windows и прокручивают целевой элемент в реальный viewport. Для визуальной матрицы используется offscreen-платформа Qt на Windows с системным шрифтом Segoe UI; JSON явно записывает `platform`, фактический размер и DPR. Изменение системного режима монитора Windows 10/11 и его штатной настройки 125% остаётся ручной проверкой; offscreen-рендер не объявляется такой проверкой.
