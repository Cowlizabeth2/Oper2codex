# ЗАДАНИЕ ДЛЯ CODEX: ПОЛНОЦЕННЫЙ РЕДИЗАЙН И ИСПРАВЛЕНИЕ «ОПЕРАТИВНОГО ЦЕНТРА»

## 1. Контекст проекта

Ты работаешь над существующим настольным Windows-приложением «Оперативный центр».

Технологии:
- Python 3
- PySide6 + Qt Quick / QML
- SQLite
- GitHub Actions для сборки Windows EXE

Репозиторий: `Cowlizabeth2/Oper`.

Программа предназначена для оперативной работы с происшествиями, документами Word/Excel, текстовыми шаблонами, контактами и рабочими файлами без интернета.

**Не создавай новую программу с нуля, если существующий проект можно качественно переработать. Работай непосредственно с репозиторием.**

Текущая версия функционально частично реализована, но интерфейс громоздкий, плохо использует пространство и не соответствует уровню современного профессионального приложения.

Твоя задача — провести полноценную переработку UX/UI, исправить имеющиеся проблемы и сохранить рабочую логику.

## 2. Главная цель

Превратить существующий интерфейс в современное, удобное, компактное настольное приложение.

Визуальные ориентиры:

- **Linear** — чёткая иерархия, спокойная тёмная тема, аккуратная навигация.
- **Raycast** — компактные элементы, плотная информация, минимальное количество лишних действий.
- **Figma / FigJam** — удобный визуальный конструктор, свободный холст, стрелки и панель свойств.
- **Notion** — понятные списки, настройки, фильтры и редактирование данных.

Не копируй интерфейсы этих продуктов буквально. Используй их принципы.

Интерфейс должен выглядеть как законченный профессиональный продукт, а не прототип.

## 3. Общая дизайн-система

Реализуй централизованную систему оформления.

Все визуальные параметры должны поступать из единого ThemeManager и дизайн-токенов.

Настройки тем сохраняются в SQLite.

Предусмотри:

- тёмную тему по умолчанию;
- полноценную светлую тему;
- единые цвета фонов, карточек, кнопок, текста и границ;
- единую типографику;
- отступы с базовым шагом 8 px и промежуточными значениями 4 px;
- скругления 8–12 px;
- единые состояния hover, pressed, focused, disabled;
- масштабирование интерфейса;
- корректную работу при изменении размеров окна и DPI Windows.

Не прописывай произвольные цвета и размеры отдельно в каждом QML-компоненте.

Используй единую библиотеку компонентов.

Для ориентировочной тёмной палитры:

- Основной фон: `#11151D`
- Боковая панель: `#181F2B`
- Карточки: `#202A38`
- Границы: `#344153`
- Основной текст: `#EEF2F8`
- Вторичный текст: `#9BAFC0`
- Акцентный синий: `#8AB4FF`

Это исходные ориентиры, а не запрет на профессиональную корректировку палитры.

Учитывай читаемость, контрастность и цветовые обозначения предупреждений.

## 4. Главное окно

Переделай компоновку.

Левая боковая панель:

- компактная;
- возможность свернуть до иконок;
- разделы «Главная», «Происшествия», «История», «Конструктор», «Настройки», «Журнал»;
- понятное выделение текущего раздела;
- без чрезмерно больших кнопок.

Верхняя панель:

- название текущей страницы;
- открытые вкладки происшествий;
- поиск там, где он необходим;
- основные действия текущей страницы;
- переключение темы через настройки или компактный переключатель.

Не дублируй одинаковые заголовки и элементы управления.

### Главная страница

Основная задача — быстрый запуск происшествий.

Мастер-блоки должны иметь компактный, современный вид.

Каждый мастер-блок показывает название, подходящую иконку и при необходимости краткое описание.

Нажатие мастер-блока всегда создаёт **новую независимую карточку происшествия**.

Нельзя переиспользовать существующую карточку вместо создания новой.

## 5. Рабочее пространство происшествия

При создании происшествия одновременно активируются все блоки, подключённые к мастер-блоку.

Например:

`ДТП → Текстовый шаблон + Контакты + Рабочие документы + Сопутствующие файлы`

Это **параллельная активация**, а не последовательное открытие.

Каждая карточка имеет собственные:
- значения текстовых полей;
- рабочие копии документов;
- состояния блоков;
- идентификатор;
- историю действий.

При переключении вкладок данные сохраняются.

Закрытие вкладки не удаляет происшествие.

При повторном запуске приложения активные карточки должны восстанавливаться.

Рабочую область сделай визуально собранной. Не оставляй один маленький блок посреди огромного пустого экрана.

При этом сохрани пользовательскую компоновку блоков: нельзя автоматически менять сохранённые координаты без согласованного правила. Используй масштабирование холста, прокрутку и команду «Вписать содержимое».

## 6. КРИТИЧЕСКИ ВАЖНО: полностью переделать TextTemplateBlock

Текущая реализация неудобна.

Сейчас программа создаёт большие вертикальные поля для каждой строки и отдельно показывает итоговое сообщение.

Это необходимо исправить.

### Режим конструктора

Разработчик должен иметь возможность:

1. Написать совершенно произвольный текст.
2. Выделить мышью нужный фрагмент либо поставить курсор после подписи.
3. Нажать «Создать поле ввода».
4. Задать название поля, тип, подсказку, обязательность и другие параметры.
5. Добавить индивидуальные готовые фразы для этого поля.
6. Сохранить шаблон.

Количество полей произвольное.

Поля могут находиться в середине предложения, после двоеточия, в нескольких местах одной строки и между обычными текстовыми фрагментами.

Не ограничивай редактор фиксированными строками «Дата» и «Место».

### Рабочий режим

Текст отображается как единое сообщение, но редактировать можно только специально созданные поля.

Пример:

Время: [__________] [▼]

Место: [__________] [▼]

Перевозчик: [__________] [▼]

Происшествие: [__________] [▼]

Пострадавшие: [__________] [▼]

Постоянный текст защищён. Поля расположены непосредственно внутри структуры сообщения.

Не создавай для каждой строки отдельную большую карточку.

Не показывай дублирующий предпросмотр под полями.

Для обычного однострочного поля используй компактный TextField. Для многострочного — поле подходящей высоты, увеличивающееся по содержимому в разумных пределах.

### Пресеты

Справа от соответствующего поля должна быть компактная кнопка раскрытия списка.

Например, у поля «Перевозчик»:

- ТМП20
- Стартранс
- Автолайн

Выбор пресета вставляет фразу в поле.

Поддержи замену содержимого или добавление через пробел согласно настройке поля.

После вставки пользователь может редактировать значение вручную.

У каждого поля собственные пресеты, связанные с постоянным ID поля.

### Копирование

Внизу блока одна основная кнопка:

**«Копировать весь текст»**

Она копирует полноценное сообщение: неизменяемые части + введённые значения + выбранные фразы.

Сохраняются переносы строк, пробелы и последовательность исходного текста.

Не включай в копируемый текст кнопки, элементы интерфейса или служебные подписи.

### Визуальные требования

- Компактные строки.
- Без лишних заголовков «Поле» над каждым значением.
- Без отдельного предпросмотра.
- Без огромных отступов.
- Корректная работа с длинными подписями.
- Прокрутка только при необходимости.
- Кнопка копирования доступна внизу блока.
- Пользователь не может изменить постоянный текст в рабочем режиме.

Существующие пользовательские шаблоны и значения должны быть сохранены и при необходимости перенесены миграцией.

## 7. Полноценный редизайн конструктора

Текущий конструктор выглядит перегруженным.

Переделай его по схеме:

**Палитра компонентов → Свободный холст → Инспектор свойств.**

### Панель инструментов

Компактно размести:
- добавление блока;
- выбор мастер-блока;
- масштаб холста;
- включение сетки;
- отмену/повтор действий;
- редактор связей;
- публикацию конфигурации.

Не размещай длинные описания функциональности в каждой кнопке.

### Рабочий холст

Должен поддерживать:
- свободное перемещение блоков мышью;
- изменение размеров за края и углы;
- привязку к сетке по желанию пользователя;
- направляющие выравнивания;
- масштабирование;
- перемещение холста;
- множественное выделение;
- копирование и дублирование блоков;
- сохранение размеров и координат;
- удобную работу с большим количеством блоков.

Свободное перемещение необходимо сохранить.

### Представление блоков в конструкторе

Вместо длинных карточек с большим количеством текста показывай:

- название;
- тип;
- состояние настройки;
- краткую информацию об источнике данных, если нужна;
- кнопку настроек.

Не нужно показывать весь текст шаблона внутри элемента конструктора, если пользователь сейчас не редактирует его.

### Правая панель свойств

Разбей на разделы:

- Общее
- Содержимое
- Поля
- Пресеты
- Источники данных
- Оформление

Показывай только те разделы, которые относятся к выбранному типу блока.

Не показывай бессмысленные параметры или поля, неприменимые к текущему компоненту.

Используй прокрутку панели, сворачиваемые группы и поиск настроек при необходимости.

## 8. Редактор связей мастер-блока

Отдельно реализуй наглядные связи между мастер-блоком и другими экземплярами компонентов.

Стрелки показывают, какие блоки активируются при запуске сценария.

Пример:

Мастер «ДТП» → Текстовый шаблон

Мастер «ДТП» → Контакты

Мастер «ДТП» → Рабочие документы

Мастер «ДТП» → Сопутствующие файлы

Все подключённые блоки активируются одновременно.

Положение карточек на холсте не определяет логику связей.

Связи сохраняются в SQLite.

Сохрани возможность создавать множество экземпляров одного типа блока с независимыми настройками.

## 9. Остальные функциональные блоки

### DocumentManagerBlock

Сохрани:
- привязку отдельных файлов и папок;
- автоматическое создание рабочих копий всех документов при создании новой карточки происшествия;
- защиту оригиналов от изменения через программу;
- повторное открытие уже созданных копий;
- открытие рабочей папки;
- независимые комплекты для разных происшествий.

### ContactsBlock

Сохрани:
- создание подготовленного Excel-справочника;
- ФИО и телефон как основные поля;
- необязательные должность и комментарии;
- фильтрацию по тегу мастер-блока;
- несколько действий для одного контакта;
- обновление данных из Excel.

Отображай контакты компактными строками. Не делай огромную карточку для каждого человека.

### ReferenceFilesBlock

Сохрани:
- подключение файлов и папок;
- список сопутствующих документов;
- безопасный просмотр;
- копирование выбранного файла или нескольких файлов в буфер Windows;
- открытие расположения файла.

Отображай файлы в компактном списке с иконками типов и действиями справа.
