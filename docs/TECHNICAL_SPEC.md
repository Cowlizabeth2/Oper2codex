# Техническое задание для Codex: «Оперативный центр»

## Роль и способ работы

Ты — ведущий инженер Python/PySide6/QML, UX-архитектор настольных приложений, инженер тестирования и сборки Windows. Твоя задача — довести существующий проект до законченного, удобного и надёжного автономного Windows-приложения **«Оперативный центр»**. Работай непосредственно с репозиторием `Cowlizabeth2/Oper`, если он доступен. Сначала исследуй существующий код и данные, а затем исправляй/рефакторь проект. Не считай прежние реализации корректными только потому, что они присутствуют в коде. Избегай косметических заглушек и имитаций функциональности.

Не задавай пользователю вопросы о требованиях, подробно зафиксированных ниже. При неоднозначностях выбирай разумный, безопасный вариант, документируй его. Не выдавай незапущенный код за проверенный. Запускай доступные тесты, устраняй ошибки, повторяй проверки. Если в среде нет Windows, организуй проверку в GitHub Actions на Windows runner и честно отрази, что проверено автоматически, а что требует ручной приёмки. Не меняй рабочие пользовательские данные при тестировании.

## 1. Назначение и условия использования

Офлайн-программа для **одного ПК с Windows 10/11**, используемая при происшествиях (ДТП, пожар, авария, «Столица», категории происшествий и любые будущие сценарии). На рабочем ПК нет возможности свободно скачивать зависимости с сайтов; пользователь работает с ChatGPT/репозиторием преимущественно с телефона. В приложении сотрудник выбирает мастер-кнопку происшествия, после чего создаётся отдельная независимая карточка/вкладка со всеми нужными блоками: текстовые сообщения, контакты, документы для редактирования, сопутствующие файлы для просмотра/отправки. Все исходные данные хранятся локально.

Пользователь должен самостоятельно настраивать страницы, создавать/дублировать блоки и менять связи, файлы, шаблоны, контакты **без пересборки EXE**. Пересборка требуется только для принципиально новых типов программных действий/модулей.

## 2. Стек и архитектура — уже согласованы

- Python 3 + PySide6 + **Qt Quick/QML** для настольного UI.
- SQLite как локальная база сценариев, блоков, связей, шаблонов, сессий, предпочтений и журналов; транзакции и миграции схемы.
- `openpyxl` для XLSX, `python-docx` при необходимости для DOCX; исходные Word/Excel открывать установленными Windows-приложениями.
- Windows clipboard для настоящего копирования **файлового объекта**, не только имени или пути; проверить совместимость в рабочих мессенджерах.
- Приложение полностью работоспособно без сети, без локального веб-сервера и без установки Python на целевой ПК.
- Разделение: UI/QML, централизованное управление темами, модели/состояние, сервисы, хранилище, файловые операции, логи, сборка/тесты.
- Данные находятся отдельно от EXE (например `%LOCALAPPDATA%\OperationalCenter`), пользовательские документы — в выбранных местах. Обновление EXE не удаляет/сбрасывает БД.

## 3. Обязательные режимы и навигация

### Рабочий режим

- Современное окно с боковым меню, домашним экраном мастер-кнопок, вкладками/карточками активных событий, историей, настройками и доступом к логам.
- Пользователь не может случайно перетаскивать, изменять размеры или удалять блоки в рабочем режиме.
- Каждое **новое нажатие** мастер-кнопки создаёт **новую независимую карточку/вкладку**, даже если уже существует ДТП или пожар. Вкладка имеет уникальный ID, название/номер, время создания и собственные значения всех полей, рабочих файлов и состояний.
- Закрытие вкладки лишь скрывает её, но не удаляет событие; повторное открытие через историю. «Завершить/архивировать» — отдельное действие.
- Несколько происшествий одновременно, между ними быстрое переключение без смешивания данных. Восстановление незавершённых вкладок после перезапуска.

### Режим разработчика / конструктор

- Создание мастер-блоков и любое количество **экземпляров каждого типа функционального блока**. Например, 3 текстовых шаблона, 2 справочника контактов, 4 файловых блока, независимо настроенные.
- Свободное перетаскивание блоков **мышью** по холсту за шапку, изменение размера за угол/край, выделение, дублирование, удаление, изменение заголовка; удобные направляющие, привязка при желании, визуальная обратная связь. **Не подменять свободное перемещение сортировкой стрелками вверх/вниз.**
- Отдельный **визуальный редактор связей** мастер-кнопки с узлами и **стрелками**. Стрелки задают связь/иерархию активации, **не последовательное открытие**: по нажатию все подключённые блоки появляются **одновременно (каскадом)**. Положение блоков на холсте независимо от связей.
- Возможность привязать/отвязать конкретный экземпляр блока, независимо от его типа. Удаление блока требует подтверждения, ссылки валидируются. Желательно экспорт/импорт набора блоков/сценария, дублирование сценария.
- Два слоя: черновик конфигурации и опубликованная рабочая конфигурация; возможность отменить/повторить и безопасно опубликовать изменения. Не сломать уже открытые карточки изменением схемы мастера.
- При масштабировании окна учитывать минимальные размеры блоков, DPI Windows, прокрутку холста, возможность увеличивать/уменьшать масштаб. Сохранённые логические координаты и размеры не должны портиться при ресайзе. Содержимое блоков адаптируется: нормальные поля ввода, перенос текста, внутренние скроллы без неуместных горизонтальных полос.

## 4. MasterBlock — главный блок

- Разработчик даёт отображаемое имя (ДТП, Пожар, ДТП 2 категории, Столица и т.д.), значок, цвет, **неизменяемый UUID**, независимый от названия внутренний тег (например `dtp`, `dtp_2`, `stolica`).
- В редакторе стрелками связывает с произвольными конкретными экземплярами остальных блоков, задаёт компоновку карточки.
- При каждом нажатии создаётся новое событие с уникальным контекстом; все связанные блоки инициализируются вместе. Блок контактов получает системный тег; документы создают рабочий комплект; текстовые шаблоны получают независимые значения.
- Повторный запуск того же мастер-блока **не возвращает прежний инцидент**, а создаёт новый. Старые доступны через вкладки/историю.
- Настройки шаблона и состав блоков, действовавшие при создании происшествия, фиксируются снапшотом/версией. Изменения в мастер-конфигурации не меняют задним числом уже существующие события.

## 5. TextTemplateBlock — полностью настраиваемый текстовый шаблон

**Критически важное требование: никаких жёстко зашитых полей «Дата» и «Место», никаких ограничений «одно поле на строку».**

- В режиме разработчика есть удобный полноценный редактор **произвольного текста**. Текст может включать любые строки, пробелы, двоеточия, абзацы, статический текст до/после вводимых значений.
- Разработчик **выделяет любой фрагмент текста** и создаёт из выделения заполняемое поле; если поле пустое, может поставить курсор и вставить поле. Выделение/разметка не привязана к `:`; варианты с автоматическим преобразованием по двоеточию **не использовать**, выбран **ручной режим**. Допускаются несколько полей в одной строке и в середине предложения.
- Каждое поле имеет стабильный ID, необязательную подпись/placeholder, тип/валидацию, обязательность, многострочность, предзаполнение. Остальные фрагменты исходного текста в рабочем режиме **заблокированы для редактирования**.
- Для **каждого поля отдельно** разработчик или уполномоченный пользователь настраивает набор готовых фраз. В примере `Перевозчик:` фразы «ТМП20», «Стартранс». В рабочем режиме рядом с полем кнопка/контроль открытия списка фраз; можно вводить своё значение, выбрать готовое, **заменить либо добавить через пробел** (конфигурируемо), а затем вручную дописать текст. Управление списком фраз не должно разрушать исходный шаблон.
- В рабочем режиме текст выглядит как единое сообщение со встроенными в соответствующие места редактируемыми полями (либо аккуратное визуально эквивалентное представление с точным итоговым предпросмотром). Не показывать вместо произвольного текста две фиксированные формы.
- Кнопка **«Копировать весь текст»** копирует статический текст + введённые значения в правильном порядке с сохранением переносов строк. Не включать служебные маркеры.
- Независимые значения одного и того же шаблона в разных событиях, автоматическое сохранение черновика; предостережение о незаполненных обязательных полях; возможность нескольких экземпляров блока.
- Модель хранения: массив/дерево статических текстовых сегментов и полей с UUID, версии шаблона, сериализация/миграции; тесты сохранения/восстановления, конкатенации текста и многократных полей внутри строки.

## 6. DocumentManagerBlock — рабочие документы с автоматическим копированием

- Разработчик добавляет один или несколько **конкретных файлов и/или папок**, выбирает рабочую папку вывода, фильтры расширений, рекурсивность обхода, отображаемое название блока.
- **Выбран режим Б:** при создании/открытии нового события и активации этого блока **автоматически создаются копии всех связанных файлов** в отдельную рабочую папку **данного конкретного события**. Не ждать ручного нажатия по файлу для создания комплекта.
- Оригиналы **никогда не изменяются через функциональность этого блока**. Файлы копируются атомарно с уникальными именами/структурой; папка вывода не должна находиться внутри исходной папки так, чтобы копии рекурсивно попадали обратно в список.
- В рабочем блоке видно имя файла, статус копирования, кнопка **«Открыть рабочую копию»** (Word/Excel/PDF по ассоциации Windows), а также **«Открыть папку рабочих файлов»**. Не открывать десятки окон автоматически после создания копий.
- Если сотрудник отредактировал, сохранил и закрыл рабочий документ, повторное нажатие открывает **ту же копию** и не создаёт новый файл. Повторное открытие вкладки/перезапуск программы тоже не пересоздаёт комплект.
- Если ранее созданная копия пропала, **не воссоздавать молча**, предупреждать и позволять явно решить ситуацию. Обновление оригинала не перезаписывает копию старого события.
- Ошибки по отдельным файлам не блокируют остальные, видны в блоке и пишутся в лог; проверка свободного места, существования путей, исключение перезаписи.

## 7. ContactsBlock — контакты из Excel с тегами

- В режиме разработчика кнопка **«Создать справочник контактов»** -> диалог выбора папки -> программа создаёт форматированный `.xlsx` с готовыми колонками, заголовками, автофильтром, закреплённой строкой, разумной шириной, текстовым форматом телефона. Дополнительно кнопка «Подключить существующий Excel» и «Открыть справочник».
- Обязательные значения **для отображения контакта**: ФИО и телефон. Остальные колонки необязательны и не мешают показу при пустых значениях.
- Предусмотренные колонки: `ФИО`, `Телефон`, `Должность`, `Теги`, `Действия`, `Комментарий`, опционально `Приоритет` и `Срок оповещения` как информация до создания отдельного модуля регламентов.
- `Теги`: один или несколько, например `ДТП, Пожар` (разделитель запятая); поиск нормализует пробелы и регистр, сопоставляет **целиком**, не по подстроке. Отображаемые имена мастер-кнопок не являются стабильными ключами; предусмотреть явное соответствие понятного Excel-тега и системного `incident_tag`.
- `Действия`: **несколько на контакт**, например `Позвонить, Написать, Отправить файл`. В рабочем режиме показать все действия, инструкции из комментария, должность при наличии, всегда ФИО и телефон. Не совершать звонок/отправку автоматически; это пока инструкции сотруднику.
- Контакты отбираются по тегу активного события, доступны поиск/сортировка, кнопка копирования номера, обновление из Excel. По возможности кэш/индекс SQLite, чтобы не читать большой XLSX на каждое нажатие. Изменения в сохранённом Excel подхватываются по обновлению/следующему открытию, а при ошибке пользователь видит явное предупреждение о неактуальных данных.
- Можно создать несколько ContactsBlock с разными файлами и настройками.

## 8. ReferenceFilesBlock — сопутствующие/справочные файлы

- Разработчик задаёт название, несколько файлов/папок, рекурсивность и фильтры.
- В рабочем режиме отображаются имена файлов, поиск, выбор **одного или нескольких** файлов (Ctrl/Shift), кнопки **«Просмотреть/Открыть»**, **«Копировать файл(ы)»**, **«Открыть папку»**.
- Файлы не копируются автоматически в постоянный рабочий комплект происшествия. Для просмотра защищать оригинал — например, открывать временную копию с очисткой в безопасный момент, без редактирования исходника через блок.
- «Копировать файл» означает поместить **файловый объект** в системный буфер Windows, чтобы можно было вставить его через Ctrl+V в поддерживающий мессенджер или Проводник. **Не только строку пути, не содержимое текста.** Если мессенджер не поддерживает, пользователь может выбрать «Открыть папку»; не утверждать, что все мессенджеры работают одинаково.
- Сценарий «Столица»: мастер-кнопка создаёт вкладку, появляются ContactsBlock с тегом «Столица» и ReferenceFilesBlock со связанными файлами, сотрудник выбирает файл и копирует его для отправки в чат.
- Сохранение настроек блока и выбранного файла в контексте вкладки; корректная обработка отсутствующих файлов.

## 9. Внешний вид и UX — обязательно профессиональный

- Удобный **современный desktop UI**, не набор стандартных прямоугольных кнопок и некрасивых полос прокрутки. Основная тема — тёмная графитовая, переключение на светлую. Стиль — сдержанная professional operations workspace, не кричащие цвета.
- Единая дизайн-система: базовые и семантические токены (фон, панель, акцент, текст, граница, успех, предупреждение, ошибка; типографика, расстояния, радиусы, состояния hover/focus/disabled, плотность, масштаб); общие QML-компоненты. **Ни одно окно не хранит собственные несвязанные хардкод-стили.**
- Темы/пользовательские предпочтения хранятся в SQLite, ThemeManager загружает в память, QML singleton/свойства транслируют значения. Без SQL-запросов от каждой кнопки. При повреждении пользовательской темы — встроенная резервная тема.
- Пример палитры dark: фон `#11151D`, панель `#1B2330`, карточка `#222D3B`, граница `#344153`, акцент `#8AB4FF`, текст `#EEF2F8`, вторичный `#9BAFC0`; light: `#F2F5FA`, `#FFFFFF`, `#E8EEF6`, `#CBD5E1`, `#2563EB`, `#172235`, `#64748B`. Можно улучшать при соблюдении контрастности.
- Боковая навигация: Главная, Активные происшествия/История, Конструктор, Настройки, Логи; вкладки событий; контекстная панель свойств лишь в режиме разработчика.
- Сетка/свободный холст, аккуратное перетаскивание, минимальные размеры, внутренний вертикальный скролл без нелепого горизонтального, корректное поведение при изменении размера окна и DPI. Сохранить логическое расположение, поддержать масштаб (например, 100/110/125/150%).
- UI на русском языке, понятные подписи: «Шаблон», «Добавить поле», «Готовые фразы», «Создать копии», «Открыть», «Копировать файлы», «Контакты» и пр. Не показывать внутренние имена классов `TextTemplateBlock` рядовому пользователю.

## 10. Сохранение, журнал, резервирование, ошибки

- Автосохранение данных событий, отдельно сохранение проекта/конфигурации конструктора, сохранение рабочего Word/Excel осуществляется самим Word/Excel по пользовательской команде.
- SQLite: транзакции, миграции, согласованные резервные снимки через backup API, возможность восстановления через UI после подтверждения, экспорт/импорт конфигурации (с проверкой версий) без потери данных. До миграции или опасной операции создавать backup.
- Логи: файл `%LOCALAPPDATA%\OperationalCenter\startup.log`, рабочий лог и журнал критических сбоев где возможно; запись исключений Python, Qt/QML warning/error, отсутствующих документов, ошибок импорта Excel, операций копирования.
- При аварийном старте показывать диагностическое окно с путём к логу; диагностический BAT удерживает консоль открытой и сообщает код выхода. Не допускать «мгновенного закрытия без следов». Низкоуровневые принудительные завершения невозможно гарантированно перехватить — не обещать обратного.
- Рабочие события и исходные документы особенно важны: удаление/перезапись/очистка — только явно и безопасно. Версия нового приложения не должна удалять пользовательскую SQLite.

## 11. Сборка и удобное обновление с телефона

- В репозитории `Cowlizabeth2/Oper` использовать workflow `.github/workflows/build-windows.yml`, чтобы **после однократной настройки пользователю было достаточно загрузить/заменить один `source_bundle.zip` в корне репозитория**. Workflow распаковывает ZIP во временный рабочий каталог, валидирует входные файлы, устанавливает зависимости на GitHub Windows runner, запускает тесты, проверяет загрузку QML и собирает автономный Windows-пакет/EXE через PyInstaller.
- Не собирать случайно устаревший `app.py`. Точка входа актуальной программы явная (`main.py`). Версия продукта отображается в UI и логах; SHA/идентификатор GitHub-коммита можно вписывать в файл версии, чтобы видеть, что пользователь запустил свежий билд.
- Проверять не только Python-синтаксис, но и **QML синтаксис/загрузку**: ранее возникали `Unexpected token ';'` в `Main.qml`; GitHub успешно создавал EXE, который не запускался. Перед публикацией artifact должен пройти smoke-test упакованного приложения с диагностикой/таймаутом в headless/доступном GUI-контексте Windows runner.
- Создать архив Artifacts с EXE, BAT `ЗАПУСТИТЬ`, `ДИАГНОСТИКА`, `ОТКРЫТЬ_ЛОГИ`, инструкцией и при необходимости установщиком, не требующим Python/интернета на целевом ПК. Не нарушать корпоративные правила безопасности, помнить, что неподписанный EXE может блокироваться ИТ-политиками.
- В обновлениях не удалять старую рабочую базу и рабочие файлы. Приложение должно корректно работать без сети после установки.

## 12. Тестирование и приёмка: обязательно, не ограничиваться компиляцией

Напиши автоматические тесты и запусти их:

1. Два нажатия «ДТП» создают **две** уникальные карточки; одновременно «Пожар» — третью. Их состояния не смешиваются; закрытая карточка восстанавливается из истории.
2. Текстовый редактор принимает произвольный абзац и поля **в середине предложений и несколько на одной строке**; вводит значения, добавляет/заменяет готовую фразу, копирует итог с точными переносами; постоянный текст нельзя изменить в рабочем режиме.
3. Создание второго экземпляра текстового, контактного и файлового блока сохраняет независимые настройки; перетаскивание/изменение размера сохраняются после рестарта, при ресайзе окна не портятся.
4. Редактор стрелок связывает мастер с конкретными блоками, сохраняет/восстанавливает связи; все блоки активируются одновременно, не ожидают завершения предыдущего; старые сессии используют корректную версию настроек.
5. DocumentManager автоматически создаёт по комплекту для двух происшествий; при повторном открытии **не** заменяет отредактированную копию; отсутствующая копия даёт предупреждение.
6. Создание отформатированного XLSX справочника, импорт контактов с пустой должностью/комментарием, точная фильтрация по нескольким тегам, несколько действий, изменение Excel и обновление.
7. ReferenceFilesBlock копирует **реальные файлы** в буфер на Windows и даёт просмотр без случайного изменения оригинала. Проверить вставку в Проводник, описать ограничения мессенджеров.
8. Смена dark/light темы синхронно меняет все элементы; настройки переживают рестарт.
9. Корректное восстановление после неожиданного закрытия, создание/восстановление резервной копии БД, запись ошибки старта в лог.
10. GitHub Windows workflow устанавливает зависимости и завершает `build` только после успешного smoke-test приложения.

Сделай короткую понятную инструкцию для пользователя: установка, создание мастер-блока, связи стрелками, создание произвольного текстового шаблона с выделением полей, настройка файлов и Excel, работа с вкладками, восстановление, диагностика.

## 13. Требования к результату и отчёту

1. Работоспособный код в репозитории с ясной архитектурой, миграциями, тестами и файлами сборки.
2. Удобный тёмный UI с переключением на светлый и реально работающим визуальным конструктором.
3. Все 5 типов блоков — MasterBlock плюс четыре функциональных — реализованы, без мнимых кнопок/заглушек.
4. Автоматизированная сборка для Windows и один ZIP как основной способ передачи обновлений в GitHub.
5. Список реально выполненных тестов и их результатов, отдельно — непроверенных платформенных интеграций; известных ограничений не скрывать.
